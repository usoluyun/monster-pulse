# Monster Pulse 资源用量记录 · 2026-10-08

## 结果

| 场景 | 时长 | 平均 CPU | 应用平均物理内存 | 应用峰值物理内存 | 子进程峰值物理内存 |
|---|---:|---:|---:|---:|---:|
| Monster 窗口开启、律动开启 | 15 分钟 | 约 6.1% | 50.0 MB | 50.0 MB | 39.0 MB |

CPU 百分比按单核时间口径计算（CPU 秒 / 墙钟秒 × 100%）。本次从采样点的累计 CPU 时间差计算，避免将应用启动后的历史 CPU 时间误计入本轮。子进程内存单独列出，不与应用内存相加；额度查询启动的 `codex` 子进程短暂出现，最高 footprint 为 39 MB。

## 环境与方法

- 系统：macOS 27.0.1（Build 26A434）。
- 被测程序：`/Applications/MonsterPulse.app`；其可执行文件与本仓库 `app/.build/MonsterPulse.app` 的 SHA-256 相同：`b396773c9c29d44cc562555d44ad6aeeeac520622eb7fe9452691a7366df0d04`。
- 采样工具：`app/tests/measure.py`，每 60 秒读取累计 CPU 时间与物理内存 footprint，共 15 个采样点、900 秒；读取已有进程，不重启或结束应用。
- 测试时主窗口处于 Monster 模式，外观设置中的“播放角色律动”为开启；测试开始时界面显示 CPU 9%、GPU 17%，满足运行律动的非零负载条件。未施加人工压力负载。
- 应用 footprint 在所有采样点保持 50 MB。平均 CPU 由约 28.54 秒的起始累计值与本轮结束累计值约 83.4 秒之差，除以 900 秒计算，约为 6.1%。

## 限制

这是一台机器、一个 15 分钟样本，且期间系统负载可能变化。没有做仪表模式对照、活动监视器对照、三轮重复、功耗 / 唤醒次数测量或其他机器测试。资源用量只能作为本机当前运行状态的记录，不能据此关闭 Monster 动画性能验收里程碑。

注意：`measure.py` 退出时打印的“平均CPU”会将进程从启动以来的累计 CPU 时间直接除以本轮时长；该行不代表本轮 CPU 均值。本记录使用采样起止差值重新计算。后续完善该脚本汇总输出前，正式结论应以 `perf-summary.py` 的区间差值汇总或等效计算为准。
