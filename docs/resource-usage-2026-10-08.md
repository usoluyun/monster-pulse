## 结果

CPU 百分比按单核时间口径计算（CPU 秒 / 墙钟秒 × 100%）。本次从应用进程采样点的累计 CPU 时间差计算，避免将应用启动后的历史 CPU 时间误计入本轮。短命的查询子进程会在两次采样间退出，其 CPU 时间无法由这份 CSV 完整追踪；表中 CPU 值只代表应用主进程。子进程内存单独列出，不与应用内存相加；额度查询启动的 `codex` 子进程短暂出现，最高 footprint 为 39 MB。

## 环境与方法

- 系统：macOS 27.0.1（Build 26A434）。
- 被测程序：`/Applications/MonsterPulse.app`；其可执行文件与本仓库 `app/.build/MonsterPulse.app` 的 SHA-256 相同：`b396773c9c29d44cc562555d44ad6aeeeac520622eb7fe9452691a7366df0d04`。
- 采样工具：`app/tests/measure.py`，每 60 秒读取累计 CPU 时间与物理内存 footprint，共 15 个采样点、900 秒；读取已有进程，不重启或结束应用。[原始采样 CSV](data/monster-resource-2026-10-08.csv)保留了可核对的逐点读数。
- 测试时主窗口处于 Monster 模式，外观设置中的“播放角色律动”为开启；测试开始时界面显示 CPU 9%、GPU 17%，满足运行律动的非零负载条件。未施加人工压力负载。
- 15 个应用 footprint 读数均为 50 MB；`footprint` 的这组输出按整 MB 计，不能据此断言内存毫无变化。CSV 首末采样点位于 0.0 秒与 841.2 秒，应用累计 CPU 从 28.54 秒增至 80.17 秒，区间平均为 `(80.17 − 28.54) / 841.2 × 100% = 6.14%`；表中按一位小数写作约 6.1%。900 秒是整次测量时长，最后约 59 秒没有新的 CSV 采样点，不纳入该区间平均值。

## 限制

这份记录足以描述本机 Monster 场景的一次持续运行：CPU 时间稳步增加，采样分辨率内未见应用 footprint 上升。对常驻 Dock 应用，持续约 6% 的单核 CPU 值得继续关注，但目前没有预设的合格阈值，不能仅凭这个数字判定通过或失败。

本次只测试 Monster 场景，未采集功耗、唤醒次数、Dock / WindowServer 的间接开销，也未在其他机型复测。它不能说明真实电池影响或跨机表现；这些仍属于 Monster 真机验收范围。

注意：`measure.py` 退出时打印的“平均CPU”会将进程从启动以来的累计 CPU 时间直接除以本轮时长；该行不代表本轮 CPU 均值。本记录使用采样起止差值重新计算。后续完善该脚本汇总输出前，正式结论应以 `perf-summary.py` 的区间差值汇总或等效计算为准。
