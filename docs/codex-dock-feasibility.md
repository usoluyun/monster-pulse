# Codex Dock：可行性分析与 PoC

日期：2026-10-04。需求：macOS 应用驻留 Dock，优先展示 **Codex 订阅额度**，兼顾 CPU 和内存；整体资源消耗低于系统活动监视器（Activity Monitor）。

## 结论与边界

可以实现。原生 AppKit 支持自定义 Dock 图标内容，系统汇总指标也可以轻量采集。但“低于活动监视器”目前是待验证的验收目标，而非已经测得的结论。必须计入获取额度所需的 Codex 子进程，以及启动尖峰、累计 CPU 时间和唤醒开销。

本项目关注 Codex 订阅额度，不是 OpenAI API 账单，也不承诺显示 ChatGPT 网页聊天中所有模型的剩余次数。接口返回的是额度窗口内已用百分比，不能可靠换算成剩余消息条数或 token 数量。

## 数据来源

### Codex 订阅

使用官方 Codex CLI 的 `app-server`，通过标准输入输出交换逐行 JSON 消息：

1. 启动 `codex app-server`。
2. 发送 `initialize`，等待成功响应。
3. 发送 `initialized` 通知。
4. 请求 `account/rateLimits/read`。
5. 读取成功响应后关闭管道并结束子进程。

读取 `rateLimitsByLimitId.codex`，兼容旧版 `rateLimits`。只展示 `primary`、`secondary` 中实际存在的窗口；窗口长度来自 `windowDurationMins`，不硬编码五小时或每周。`usedPercent` 表示已用百分比，剩余量为 `100 - usedPercent`，`resetsAt` 是 Unix 秒时间戳。

若多额度桶响应没有 `codex`，不擅自使用其他产品额度。空字段、权限不足、网络异常、未登录或版本不兼容应显示不可用；失败后已有快照可以保留，但必须标明旧数据和更新时间。没有新响应时，重置时间到了也不能自行宣布额度恢复。

PoC 复用 CLI 管理的现有登录状态，不读取、复制或输出 token，不调用模型推理，不创建会话。用户需事先使用 ChatGPT 订阅方式登录 Codex CLI。桌面 App 与 CLI 是否共享可用登录状态需实际验证，不能仅凭桌面已登录推断。

### CPU 和内存

- CPU：读取 `host_statistics(HOST_CPU_LOAD_INFO)` 的累计 tick，以相邻采样差值计算系统整体忙碌率；首次采样显示等待，唤醒后重置基线。
- 内存：读取 `host_statistics64(HOST_VM_INFO64)`，以 `(active + wired + compressor pages) × page size / physical memory` 显示近似占比。
- 内存近似占比不是内存压力，也不等于活动监视器的“内存已使用”；不能用两个不同定义的数值做正确性对比。
- 不遍历进程，不启动 `top`、`ps` 等命令采集常规指标。

## 实现选择

使用 Swift + AppKit，直接绘制 `NSDockTile.contentView`，无第三方依赖、浏览器运行时或连续动画。Dock 显示主窗口剩余百分比，青色条表示 CPU，紫色条表示内存。点击图标打开详情，关闭详情后保持运行，通过菜单或 Command-Q 退出。

系统指标每 5 秒刷新，定时器容差 1 秒；额度每 120 秒刷新，容差 15 秒，并提供手动刷新。睡眠时暂停计时器并取消查询，唤醒后重新采样。查询不能重叠，单次等待上限约 20 秒，清理阶段额外最多约 1 秒后强制终止仍存活的子进程。

PoC 采用按需启动辅助进程，避免辅助进程常驻。但这不代表它一定最节能：反复启动会产生 CPU、磁盘和网络开销。后续应测量与常驻辅助进程方案的差异，再选择策略。CLI 自身可能维护状态、日志或刷新认证；“只读查询”指不执行推理和项目操作，并非保证 CLI 完全不写磁盘。

## 性能验收方法

在同一台 Mac、同一系统版本、相同供电与工作负载下，用 Release（`-O`）版本进行对比。分别运行两者，避免把同时运行监控工具的影响忽略掉；至少重复三次。

| 场景 | 测量条件 |
| --- | --- |
| 常驻基线 | 详情关闭、Dock 可见，系统刷新周期一致（5 秒） |
| 打开详情 | 双方窗口可见，记录活动监视器所选页面和进程范围 |
| 完整额度周期 | 预热后持续至少 15 分钟，涵盖多次查询及所有子进程 |
| 异常路径 | 未登录、断网、超时、睡眠与唤醒、查询期间退出 |

记录应用与子进程合计的累计 CPU 时间、平均 CPU、物理内存 footprint、峰值内存、唤醒次数；可用 Instruments / 系统性能工具进行正式采样。`ps` 的 RSS 只能用于粗略观察，不等于物理 footprint，简单相加还可能重复计入共享页。也应关注 Dock/WindowServer 因图标重绘产生的间接开销。

验收以完整周期平均 CPU 和平均内存低于活动监视器为基本条件，同时检查峰值及能耗是否出现不可接受的回退。具体可接受差值应以本机基线建立，PoC 不预先编造 MB 或百分比承诺。若不达标，优先减少重绘、降低额度轮询频率、比较辅助进程生命周期策略。
