## M1 · Dock 状态仪表（已完成）

当前阶段：macOS 常驻应用、Codex 订阅额度与重置时间、网络出口、系统采样、详情与设置、Dock 跳动预警、开机自启，以及构建、自检和异常路径验证。

本次收尾：Dock 右侧以 2×2 布局展示 CPU / GPU / 内存 / 磁盘，设置支持四项独立显示与隐藏。磁盘格内左侧橙色为读、右侧黄色为写，固定满格 800 MB/s；内存紫色，CPU 青色、GPU 绿色。关闭的指标连底槽一起隐藏，剩余柱状图动态扩展：三项时同列剩余项拉满，两项为双长柱，一项占满计量区。主界面右下角提供设置入口。采样继续运行以供详情和预警使用。

限制保留：内存为页面统计估算，磁盘为 pageins/pageouts 换算，不等于全量磁盘 I/O；GPU 接口未文档化。阶段完成不意味着这些数据口径或小尺寸可读性限制已解决。

## M2 · Monster 状态表达（原生功能已实现，验收中）

目标：在现有仪表界面之外提供 Monster 界面，通过角色表情、姿态或形态变化，让系统负载高低与 LLM 剩余额度一眼可辨。

已实现：

- 仪表 / Monster 模式同步切换主窗口与 Dock，每次启动默认仪表。
- 身体白色面积表示 5h 剩余额度，背景太阳高度表示周剩余。
- 外圈表示 5h 时间、内圈表示周时间，两个完整圆角环独立增长；主窗口显示时间比例与重置倒计时，未知 / 到期不伪造新窗口。
- 地面颜色表示系统代理开启 / 关闭 / 未知，无代理灯与负载线条。
- CPU 上下律动、GPU 横向伸缩，隐藏对应指标后停止动作；精确数值与内存、磁盘继续在仪表查看。
- 六种颜色（含两种环色）、角色大小、动作强度、动画开关及恢复默认外观。
- 未知 / 旧快照状态、固定夹具、视觉回归与面积 / 地面 / 动作语义检查。

设计与当前行为见 [Monster 视图设计与实现](monster-view-design.md)。本机已点验主窗口与外观入口，单帧绘制微基准已测；2026-10-08 完成当前安装版 Monster 动画 15 分钟资源采样，结果与限制见[资源用量记录](resource-usage-2026-10-08.md)。按当前需求，资源测试聚焦 Monster 场景；该次为单机、单轮、无人工压力负载的观察，功耗 / 唤醒次数与不同机器的 43pt 繁忙辨识度仍待真机验证，因此里程碑保持打开。旧版仪表的性能结果不作为本轮 Monster 动画的证据。

## M3 · New API 用量接入（仅规划）

目标：用户配置自己的 New API 服务后，查看模型消耗、剩余额度及其来源，并可作为 Dock / Monster 的额度来源。

实施前调研：确认用户部署版本、实际可用接口、身份凭据类型、权限、额度单位与计费换算。**接口和字段尚未验证**，不预设一定可取得余额、周期限额或模型明细。

范围：

- 设计额度来源适配层，保留 Codex，避免把不同单位强行合并成一个百分比。
- 配置服务地址及认证方式，凭据进入安全存储；日志与截图脱敏。
- 支持实际接口能提供的余额 / 用量 / 模型明细，明确统计周期、单位和更新时间。
- 支持来源选择、代理、刷新、超时、认证失败、协议不兼容与过期快照。

验收：对照用户真实 New API 服务核对数值与单位；不能取得的字段明确不可用；服务失败不影响 Codex 和系统采样；GUI 启动验证网络、凭据与刷新行为；增加解析和异常路径验证。

## M4 · OpenCode Zen / Go 用量接入（仅规划）

目标：分别支持 OpenCode Zen 与 Go，用统一入口查看各来源的可用额度与消耗。

实施前调研：分别确认 Zen、Go 的认证、订阅 / 计费模式、官方可用接口和数据口径。**两项能力均未验证**；不从 Zen 的可行性推断 Go，也不把余额、订阅额度与 token 用量当成同一量纲。

范围：

- 复用 M3 的来源适配结构，分别实现 Zen、Go 数据源。
- 提供账户 / 来源选择，明确展示单位、统计窗口和重置时间（仅在来源提供时）。
- 让所选来源驱动 Dock / Monster，详情保留来源标识，不默认汇总不可比的额度。
- 每个来源独立处理认证失败、缺失字段、超时、限流和过期快照。

验收：Zen、Go 分别以真实账户对照核验；分别验证 GUI 网络环境和凭据；来源切换、错误隔离和回归通过。若某来源没有可用接口，先记录限制并调整范围，不用模拟值冒充接入完成。

## M5 · 真机性能指标上报（远期规划）

目标：在用户真实设备上取得不同机型、系统版本与显示模式的应用性能数据，为 Monster 动画的后续优化提供证据。M2 的本机验收不依赖 M5；上报是跨机器、持续观察能力，放在多来源接入之后单列里程碑更清晰。

交互规划：上报设置默认为开启。功能上线后的首次启动（包括已有用户升级）显示一次明确提示，提供“保持开启（默认）”和“关闭上报”两个选择；用户作出选择前不发送数据，选择后持久化。Dock 图标右键菜单和主界面设置都提供“上报性能指标”开关，两个入口实时同步；关闭后立即停止上报所需采集与上传，并丢弃尚未发送的数据。后续启动不重复询问，除非用户主动重新设置。

数据边界：只规划上报汇总后的 CPU、应用物理内存、动画运行与可取得的能耗 / 唤醒指标，以及应用版本、macOS 版本和粗粒度机型信息。不上报额度、账号、令牌、代理地址、文件路径、IP 或设备唯一标识。实现前还需确定接收端、字段精度、采样与上传频率、缓存上限、保存期限及可见的隐私说明；无网络和发送失败时不能干扰应用正常运行。

验收：至少在不同真机上核对上报数据与本机性能工具的口径；确认首次提示、默认选项、两个入口开关及重启后状态一致；确认关闭后无数据传输、无残留待发送队列，并检查上报本身的 CPU / 内存 / 能耗开销。目前仅规划，不创建上报任务或联网传输。
